# Корпоративная почта Niktrade: допущения

Дата: 2026-07-13.

Все допущения ниже должны быть пересмотрены перед production-включением почты.

## Идентификация и сотрудники

- `App\Models\User` является моделью сотрудника и учетной записи для MVP.
- Keycloak в текущем проекте не используется, поэтому MVP не добавляет Keycloak.
- `users.email` сейчас участвует в авторизации и остается существующим login/primary email до отдельного согласованного изменения.
- Корпоративный адрес почтового ящика хранится в `employee_mail_profiles.email`.
- Карточка сотрудника остается источником ФИО, статуса сотрудника и состояния жизненного цикла.
- Автоматическая смена корпоративного email после изменения ФИО не входит в MVP. В MVP меняется display name mailbox, но адрес остается стабильным.

## Почтовая инфраструктура

- Mailcow запускается отдельным dockerized-проектом и не становится частью Laravel/Vite проекта.
- Приложение не читает внутренние БД/volumes mailcow.
- Браузер не получает IMAP/SMTP credentials и не подключается к mailcow напрямую.
- Mailcow Admin API используется только backend/worker-кодом.
- До настройки DNS/MX/PTR/TLS внешняя доставка считается не включенной.
- На сервере нужно установить или включить docker compose plugin до установки mailcow.

## Очереди и outbox

- Для MVP используется существующая Laravel database queue.
- Redis, RabbitMQ или другой broker не добавляются.
- Transactional outbox добавляется в БД Niktrade отдельной таблицей.
- Провижининг должен быть идемпотентным: повторное выполнение одного события не создает дубликаты.

## Credentials и секреты

- App-password mailcow хранится только в зашифрованном виде.
- Для первого MVP допустимо использовать Laravel encryption cast на основе `APP_KEY`, если отдельный `MAIL_CREDENTIALS_MASTER_KEY_FILE` еще не подготовлен. Перед production нужно утвердить master-key strategy.
- Секреты читаются из env/secret files и никогда не попадают в frontend, git, логи, уведомления и exception messages.
- Ротация app-password должна быть отдельным действием и не должна менять пользовательский пароль.

## Backend mail gateway

- Тела писем и вложения не хранятся в БД Niktrade как источник истины.
- Niktrade может хранить только служебные ссылки, кеш метаданных и состояние UI, если это понадобится позднее.
- Поиск body text в облегчённом MVP не обязателен.
- HTML писем должен санитайзиться перед отображением.
- Удаленные изображения по умолчанию заблокированы.

## UI и проверка

- Почтовый frontend должен использовать существующий Niktrade Work UI и единую мобильную нижнюю панель.
- Filament CRUD глобально не переделывается.
- Визуальную проверку admin UI выполнять на preprod после деплоя, а не в локальной Laravel-среде.
- Документационные изменения не требуют браузерной проверки.

## Production-границы

- Codex не меняет production DNS, MX, PTR, firewall и реальные секреты автоматически.
- Для таких действий готовятся инструкции и примеры, а включение делает администратор.
- Разворот mailcow на текущем сервере считается staging/dev-профилем до отдельного production-решения.
