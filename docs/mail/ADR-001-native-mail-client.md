# ADR-001: Нативный почтовый клиент через backend gateway

Дата: 2026-07-13.

## Статус

Принято для MVP.

## Контекст

Niktrade должен предоставить сотрудникам корпоративную почту внутри существующего интерфейса и текущей web-сессии. Mailcow выбран как почтовый сервер, но его webmail/SOGo не должен становиться основным iframe-интерфейсом сайта.

Браузер не умеет безопасно работать с IMAP/SMTP напрямую в рамках требований проекта: пришлось бы раскрывать учетные данные mailbox или создавать отдельный auth-контур.

## Решение

Реализовать нативный раздел "Почта" в Niktrade.

Схема:

- браузер работает только с Niktrade backend по HTTPS и текущей сессии;
- backend подключается к IMAPS/SMTP mailcow через per-mailbox app-password;
- provisioning worker управляет mailbox и app-password через mailcow Admin REST API;
- app-password не показывается сотруднику и хранится только зашифрованным;
- SOGo может остаться аварийным/административным webmail, но не основным UI.

## Последствия

Плюсы:

- единый UX Niktrade;
- сотрудник не вводит второй пароль;
- IMAP/SMTP credentials не уходят в браузер;
- можно централизованно проверять RBAC, аудит и лимиты;
- перенос mailcow на другой сервер потребует изменения конфигурации, а не бизнес-кода.

Минусы:

- backend должен реализовать MailGateway;
- нужно аккуратно обработать HTML писем, вложения, таймауты и ошибки IMAP/SMTP;
- для полноценной производительности может понадобиться кеш метаданных писем после MVP.

## Не принимаем

- iframe SOGo как основной почтовый клиент;
- прямой IMAP/SMTP из браузера;
- хранение писем в БД Niktrade как источник истины;
- чтение внутренних таблиц/volumes mailcow из приложения.
